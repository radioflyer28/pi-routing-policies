# Bounded dialogue and explicit session affinity, not a second memory system

Status: accepted for S04 implementation.

Short follow-ups need conversational context, but a selector cannot decide which unseen history it needs. Use operator-configured, deterministic bounded dialogue admission and optional session affinity, borrowing the patterns described in [the context review](../ROUTING-CONTEXT-REVIEW.md). Defer durable task briefs, inferred task boundaries, automatic summaries and abstention-to-coordinator fallback: these add memory/workflow ownership that does not belong in this router.

## Contract

- Existing policies retain per-user-turn selection and the 3000-character latest-user prefix. New native-only configuration is `nativeRouting`; library/tool state and diagnostic preview remain explicitly caller supplied.
- `nativeRouting.context` opts into bounded recent dialogue. Defaults inside this object are three previous messages, 8000 history characters, 3000 characters per message, user-only history and head-tail truncation. `includeAssistant: true` explicitly admits assistant text so “yes” can refer to a proposed plan. All character counts are UTF-16 code units, not tokens; clipping must not split surrogate pairs. The existing 16 KiB serialized-state limit still applies, including JSON escaping.
- Only text from actual user/assistant messages in the active request and Pi's current session projection is admitted. No tool results/arguments, reasoning, system messages, custom messages, execution guidance or compaction/branch summaries masquerading as user messages. Do not recover compacted-away text from the raw transcript. Text pasted by a user or repeated in an assistant's prose remains admitted text and may contain secrets; this is not redaction.
- The current user message has priority. History is selected newest-first within the configured limits and presented chronologically. Head-tail clipping is visible; prefix clipping and rejection of oversized selected text are explicit alternatives. Context metadata contains counts and truncation flags only, never excerpts in routing notices/receipts.
- `nativeRouting.affinity: "session"` opts into assignment reuse across user turns for the same native selection and selection epoch. Default `"turn"` preserves current behavior. Every reuse revalidates policy, physical identity/auth and input support. Revocation or policy mismatch fails closed; it does not silently reclassify or substitute a model.
- `/vmodel reselect` (also `/virtual-model reselect`) resets the current automatic assignment without inference, model switching or changing context-sharing policy. The next normal request selects again and may incur selector charges. This is an assignment reset, not deletion of dialogue; recent history is still governed by context settings. It rejects explicit/physical selections. Existing explicit selection commands and manual model changes also invalidate the pin.
- Unchanged reload/resume and compaction preserve the assignment. Branch navigation/forks inherit only state on their ancestry, with subsequent resets isolated to that branch. A new session has no pin. No global cache, idle TTL or hidden task-change heuristic is added. An in-flight result cannot dispatch or attach receipts to a replaced session/abandoned branch or changed selection epoch.
- Direct/compaction calls never classify. They reuse a valid assignment or the existing explicitly configured direct target. A stale/ineligible matching pin still errors. Role guidance remains transient execution context, not routing input.

## Consequences

Session affinity deliberately trades responsiveness to changed tasks for stable selection; operators must reselect when work changes. Bounded dialogue can still omit important context, and head-tail clipping can miss middle requirements. Neither mechanism proves better live routing quality. User/assistant fixture tests establish input/lifecycle mechanics only; the frozen S03 corpus remains unchanged. Policy changes include these native options in revision identity, invalidating older assignments. No new coordinator tool capabilities or permissions are introduced.
